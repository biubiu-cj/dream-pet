# DreamPet 长期记忆实现说明

> 目标：关闭浏览器、甚至重启后端后，伙伴依然记得孩子的名字、兴趣、完成的任务和重要经历。
> 原则：结构化存储 + 摘要 + 按需检索。**不引入向量数据库，不全量塞聊天记录。**

## 1. 五层记忆模型

| 层级 | 存储位置 | 内容 | 写入时机 |
|---|---|---|---|
| 伙伴档案 | `pets` | 名字、种类、性格、等级、阶段 | 创建/修改伙伴 |
| 兴趣记忆 | `user_interests` | 恐龙、宇宙…（去重） | 创建时选择；聊天中提取 |
| 事件记忆 | `memories` (type=event) | 「孩子说想成为科学家」等 | 聊天提取；任务完成 |
| 画像记忆 | `memories` (type=profile) | 非隐私的偏好画像 | 聊天提取 |
| 任务记忆 | `tasks` | 历史/进行中任务及完成状态 | 任务生成与完成 |
| 对话摘要 | `conversation_summaries` | 滚动摘要（≤150字/条） | 未摘要消息 ≥ 20 条时 |

聊天原文保存在 `chat_messages`，但**只会读取最近 10 条**进入 Prompt。

## 2. 记忆写入流程（聊天后）

```
用户消息 → SafetyGuard 检查 → 生成回复 → 保存两条消息
                                      ↓（异步，不阻塞响应）
        MemoryManager.extractAndSave：
          Prompt 输入：已有兴趣 + 本轮对话
          输出 JSON：{"interests":[],"events":[],"profile":""}
          → 兴趣去重后写 user_interests（唯一约束兜底）
          → 事件 7 天内相同内容去重后写 memories(importance=3)
          → 画像去重后写 memories(type=profile)
          → 新兴趣同时记一条事件记忆（importance=2）
        MemoryManager.maybeSummarize：
          统计 covered_until 之后的消息数，≥20 条时把最早 ≤40 条滚动摘要
        GrowthService.addChatExp：+2 经验/次，每日上限 20
```

- 运行时：以上提取/摘要由真实文本 LLM 完成（严格 JSON 输出）。
- 离线单测：使用测试源码中的确定性客户端，不访问网络、不产生费用。
- **记忆提取失败不影响聊天主流程**，只记录警告日志（不记录聊天原文）。

## 3. 上下文组装（聊天时）

```
System Prompt =
  伙伴档案（名字/种类/性格/等级/阶段）
  + 用户兴趣（最多 10 个，按最近）
  + 最新对话摘要
  + 高重要度事件（最多 5 条）
  + 当前进行中的任务
  + 安全与语言风格约束（≤120字、提问引导、儿童向）
历史消息 = 最近 10 条 user/assistant 对话
本轮用户消息
```

Token 规模稳定可控，不会随聊天历史线性增长。

## 4. 重新进入时的「欢迎回来」

`GET /api/chat/history?greeting=true`（距上次用户消息 >30 分钟时）：

- 从数据库读取：兴趣、最近一次**已完成任务**标题、最近重要事件、距上次聊天天数；
- 生成欢迎语并**写入聊天记录**，通过 `greeting` 字段返回；
- 欢迎语始终基于上述真实数据库数据生成（测试时可把空闲阈值设为 0 便于即时验证），重启后能说出「上次我们一起完成了『恐龙小侦探』」，不是写死文案；
- 若从未聊天（新伙伴），返回 `greeting=null`，由创建完成页引导首次对话。

## 5. 去重与防膨胀

| 风险 | 措施 |
|---|---|
| 兴趣重复 | `UNIQUE(user_id, interest)` + 插入前查询 |
| 事件重复 | 7 天内完全相同的内容不再写入 |
| 摘要无限增长 | 每 20 条未摘要消息滚动合并，`covered_until` 记录覆盖位置，只取最新摘要 |
| 上下文过长 | 只取最近 10 条对话 + 5 条事件 + 10 个兴趣 |
| 隐私 | 提取 Prompt 明确禁止姓名/学校/住址/电话；SafetyGuard 输入侧另行拦截 PII |

## 6. 重启恢复验证方式

1. 创建伙伴「星星」，聊天说「我最喜欢恐龙，我想成为科学家」；
2. 生成并完成「恐龙小侦探」任务；
3. 停止后端进程，重新启动；
4. 前端重新进入聊天页 → 欢迎语应引用真实任务/兴趣数据；成长档案显示经验与事件仍在。

H2 本地数据文件位于 `backend/data/`；CloudBase 生产环境数据在 PostgreSQL 中，天然持久化。

## 7. 为什么不用向量数据库

- 数据规模：单个孩子数月互动产生的兴趣/事件只有几十~几百条；
- 检索需求：按类型 + 时间 + 重要度即可满足，语义检索收益有限；
- 成本与复杂度：向量库会产生额外资源点与运维成本，比赛与免费套餐场景不划算。
- 预留扩展：`memories` 结构可平滑迁移到 pgvector（CloudBase PostgreSQL 亦支持），后续需要时再引入。
